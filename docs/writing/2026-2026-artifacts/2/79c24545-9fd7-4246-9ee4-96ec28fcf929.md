## 순탄할 줄 알았던 70편 대량 마이그레이션

`AI 생성기` 와 `Playwright` 를 연결해 매일 새 글을 발행하는 파이프라인을 구축한 뒤, 그동안 블로그에 쌓은 글들을 둘러보니 <span style="color: var(--color-accent-spec);">자동화를 도입하기 전에 올린 글들은 태그가 하나도 달려 있지 않았고, 본문 글자 크기나 폰트, 색상도 중간중간 서로 제각각이어서 통일성을 해치고 있었다.</span>

## 네이버 블로그의 `2페이지` 와 `iframe`

블로그 글 목록에서 페이지네이션을 이용하여 이동해 글들을 순회하며 수정하는 매우 일반적인 형태다. 그런데 이상하게 스크립트가 딱 2페이지까지만 작업을 수행하고, 3페이지부터는 <span style="color: var(--color-accent-spec);">페이지 넘김을 인지하지 못한 채 무한 대기 상태에 빠지거나 뻗어버리는 현상이 계속 반복되었다.</span> 원인을 보니 네이버 블로그 `데스크톱 웹 특유의 중첩 iframe 구조(#mainFrame)` 때문이었다.

- 겉보기에는 단일 URL 같지만 실제 컨텐츠와 페이지네이션은 내부 iframe 안에서 비동기 AJAX 로 렌더링
- 자동화 도구가 페이지 번호를 클릭했을 때 네트워크 응답 지연과 SPA 스타일의 DOM 재렌더링 타이밍이 어긋나면서, `page.wait_for_selector()` 가 타임아웃을 일으키거나 이전 페이지의 캐시된 DOM 을 다시 참조하는 오류가 발생

## UI 크롤링 대신 HTTP 리버스 엔지니어링
글 목록을 가져오는 데 굳이 무거운 크롬 브라우저를 띄워서 페이지 버튼을 누를 필요가 있을까하는 생각이 들었고, 개발자 도구의 네트워크 패킷을 확인했다. <span style="color: var(--color-accent-impl);">카테고리별 글 목록 데이터를 가볍게 반환하는 엔드포인트를 확인했다.</span>

브라우저 UI 페이지네이션 클릭 로직을 제거하고 httpx 비동기 병렬 요청으로 전환하자, <span style="color: var(--color-accent-impl);">70편 전체의 글 번호와 제목, 작성일을 수집하는 시간이 2분 이상 + 간헐적 실패에서 단 2.1초 + 성공률 100% 로 약 60배 단축되었다.</span>

## 한글 형태소 태그
목록을 빠르게 가져왔으니 이제 제목에서 태그를 뽑아낼 차례였다. 처음에는 단순히 제목 문자열을 공백으로 분리한 뒤 걸러내는 방식을 썼는데, 결과물은 참담했다.

```
입력 제목: "기억을 거래하는 신비한 은빛 상점"
추출된 태그: ['#기억을', '#거래하는', '#신비한', '#은빛', '#상점']
```

<span style="color: var(--color-accent-spec);">`#기억을`, `#거래하는` 처럼 조사나 동사/형용사의 활용형이 고스란히 태그에 붙어 나왔다. SEO 관점에서 이런 태그는 가치가 없다.</span>

제대로 형태소를 분석하려면 보통 KoNLPy(Mecab, Okt 등) 같은 라이브러리를 쓰지만, 취미로 시작한 간단한 자동화를 위해서 구축하기엔 배보다 배꼽이 커지는 상황이 된다. 결국 <span style="color: var(--color-accent-impl);">외부 의존성 없이 순수 파이썬 내장 `re` 모듈만으로 처리하기로 했다.</span>

```python
# 1. 동사/활용형 어미 제거 정규식
VERB_STRIP_REGEX = re.compile(
    r'(?:하다|하는|하며|하고|했던|하여|되는|된|되며|되고|위한|통한|따른)$'
)

# 2. 관형사형 형용사 필터
ADJ_STRIP_REGEX = re.compile(
    r'(?:있는|없는|같은|어떤|모든|새로운|깊은|높은|밝은|어두운|신비한|거대한|작은|따뜻한|차가운)$'
)

# 3. 단어 원형 파괴를 방지하는 후방 탐색 조사 제거
# 앞 글자가 한글 완성형 음절이고, 최소 2음절 이상인 경우에만 말미의 조사를 제거
JOSA_STRIP_REGEX = re.compile(
    r'(?<=[가-힣]{2})(?:에서|에게|으로|로|의|과|와|을|를|은|는|이|가|도)$'
)
```

핵심은 3번의 정규식 후방 탐색((?<=[가-힣]{2}))이다. 최소 2음절 이상의 한글일 때만 끝에 붙은 조사를 제거하도록 했다.

```
입력 제목: "기억을 거래하는 신비한 은빛 상점"
[1] 조사 제거: '기억을' -> '기억'
[2] 동사 어미 제거: '거래하는' -> '거래'
[3] 관형사 필터링: '신비한' -> 제거
[4] 명사 수집: '은빛', '상점'
최종 생성 태그: ['#기억', '#거래', '#은빛', '#상점', '#판타지소설']
```

## 왜 본문 스타일이 안 바뀌지?

태그 추출한 뒤, 기존 글들의 서식을 통일하기 위해 스마트에디터 수정 페이지(`postwrite?logNo={logNo}`)로 진입했다. 목표는 본문 전체를 선택해 `기본서체`, `크기 15pt`, `기본 글씨색` 으로 일괄 변경하는 것이었다. 

### 에디터 본문 전체선택

- 페이지 전체에서 `page.keyboard.press("Control+A")` 를 호출했더니, 에디터 본문뿐만 아니라 상단 툴바, 제목 입력란, 사이드 패널까지 웹페이지 전체가 파랗게 블록 지정되면서 에디터 내부 포커스가 완전히 풀려버렸다.
- <span style="color: var(--color-accent-impl);">첫 번째 단락 컨테이너(`.se-component-content`)를 찾아 클릭한 뒤 `Control+A` 를 전송함으로써, 오직 '본문 텍스트 블록' 전체 선택이 되도록했다.</span>


### 색상 팔레트에 커스텀 색상선택

- 에디터 상단 툴바의 글자 색상 버튼을 누르면 기본적으로 72가지 고정 색상 팔레트만 나타난다. 팔레트에 없는 특정 색상 (예: #2c3e50) 를 입히려면,

1. 팔레트 하단의 `더보기` 버튼(`.se-color-picker-more-button`)을 클릭
2. <span style="color: var(--color-accent-impl);">숨겨져 있던 HEX 입력 필드(`input.se-selected-color-hex`)가 활성화</span>
3. 기존 값을 지우고 원하는 HEX 코드를 입력한 뒤 Enter 키를 전송

```python
async def apply_font_color(page: Page, hex_color: str):
    # 1. 글자 색상 툴바 열기
    await page.locator("button[data-name='color']").click()
    
    # 2. 72개 기본 팔레트에 일치하는 색상이 있으면 1클릭으로 즉시 적용
    palette_btn = page.locator(f"button.se-color-palette-btn[data-color='{hex_color.lower()}']")
    if await palette_btn.count() > 0:
        await palette_btn.first.click()
        return
        
    # 3. 커스텀 HEX인 경우 더보기 피커를 열어 인풋에 직접 주입
    more_btn = page.locator(".se-color-picker-more-button")
    await more_btn.click()
    hex_input = page.locator("input.se-selected-color-hex")
    await hex_input.fill(hex_color.lstrip("#"))
    await hex_input.press("Enter")
```
