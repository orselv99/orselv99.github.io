## 1. 개요 및 문제 정의

델타 패치 적용 시 누적 패치가 과도하게 많아지면 시스템 안정성이 저하될 수 있으며, 특히 여러 버전을 건너뛴 사용자의 경우 다운로드 크기 증가 및 적용 실패 확률이 상승합니다. 이러한 문제를 해결하기 위해 진행 명세서(Manifest)를 로컬에 영속화하고, 중단된 다운로드를 해당 체크포인트부터 재개하는 메커니즘을 설계했습니다.



## 2. 해결 아키텍처

### 2.1 단계별 처리 흐름

#### 2.1.1 1단계: 규칙 기반 1차 필터
델타 패치 적용 전에 로컬에 저장된 진행 명세서(Manifest)를 기반으로 다운로드 여부를 1차적으로 판정합니다.
- **누적 패치 임계치 검사**: 과거 기록을 토대로 현재 버전까지 도달하는 데 필요한 누적 패치량을 계산합니다.
- **분기 처리**: 임계치를 초과하면 대용량 전체 다운로드로 분기하고, 임계치 이하이면 델타 패치 처리를 계속 진행합니다.

#### 2.1.2 2단계: LLM 기반 2차 판정
델타 패치 적용 후 LLM을 통해 최종 적용 가능성을 판정합니다.
- **LLM 추론**: 전체 패치 목록과 현재 버전 정보, 이전 버전의 알려진 이슈 등을 LLM에게 전달하여 적용 가능 여부를 판단합니다.
- **고도화된 적용성 분석**: 단순 패치 적용 여부를 넘어, 여러 버전을 건너뛴 경우 발생할 수 있는 비호환성, 데이터 손상 가능성 등을 심층적으로 분석합니다.



### 2.2 지속성 메커니즘

#### 2.2.1 진행 명세서(Manifest) 영속화
각 버전별 패치 다운로드 시 진행 명세서를 로컬에 영속화하여 상태를 기록합니다.
- **로컬 저장**: 다운로드된 패치 목록, 적용 상태, 버전 정보를 로컬 파일로 저장합니다.
- **재사용성**: 시스템이 재시작되거나 다운로드가 중단되더라도 진행 상태를 복구할 수 있습니다.

#### 2.2.2 중단 지점 재개
다운로드 또는 적용 중단 시, 저장된 체크포인트를 기반으로 다운로드를 재개합니다.
- **체크포인트 기반 복구**: 진행 명세서에 기록된 체크포인트를 기반으로 손실된 패치부터 다운로드를 재개합니다.
- **자동 재시도**: 네트워크 오류 등으로 다운로드가 실패한 경우, 자동으로 다운로드를 재시도하여 안정적인 패치 적용을 보장합니다.



## 3. 기대 효과

- **시스템 안정성 향상**: 과도한 델타 패치 적용으로 인한 시스템 불안정성 감소
- **다운로드 효율 증대**: 여러 버전을 건너뛴 사용자에게 대용량 전체 다운로드로의 분기 적용
- **자동 복구 기능**: 다운로드 중단 시 체크포인트 기반 자동 재시작으로 사용자 개입 최소화
- **데이터 무결성 보장**: LLM 기반 2차 판정으로 잠재적 데이터 손상 방지
