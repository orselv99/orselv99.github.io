### 카카오 카나나 세이프가드 프롬프트 주요 특징
- 한국어/영어 최적화 경량 모델 : 2.1B 매개변수 규모의 경량 특화 모델로, <span style="color: var(--color-accent-impl);">대규모 LLM 대비 매우 빠른 레이턴시(수십 ms 단위)와 낮은 VRAM  점유율로 전처리 게이트웨이에 최적화</span>되어 있다
- 토큰 기반 직접 제어 및 스트리밍 판별 : 생성 기반의 일반 텍스트 추론 대신 판별용 특수 토큰(`<UNSAFE-A1>`, `<UNSAFE-A2>`, `<SAFE>` 등) 을 <span style="color: var(--color-accent-impl);">단일 토큰 레벨에서 즉시 출력하도록 파인튜닝되어 있어 디코딩 오버헤드가 없다</span>
- 다양한 우회 공격 패턴(Evasion) 사전 학습 : Base64/인코딩 난독화, 페르소나/평가자 역할 부여(Jailbreak), RAG 간접 주입(Indirect Injection), JSON/마크다운 스키마 강제 등 <span style="color: var(--color-accent-impl);">실무 공격 기법에 대한 견고한 분류 성능을 보인다</span>
- 파이프라인 비용 절감 : LLM 에 전달하기 전 유해·악의적 입력을 조기 차단(Early Exit) 함으로써 <span style="color: var(--color-accent-impl);">불필요한 메인 모델의 Context KV Cache 낭비 및 추론 비용을 방어한다</span>

## LLM(Gemma4) 과 Kanana Safeguard Prompt 차이
> 생성형 LLM 이 스스로 위험을 판단하고 거절할 수 있다면 별도 가드 모델을 둘 이유가 없다.

원칙적으로는 사실이다. 만약 범용 LLM이 모든 기만적 입력과 인젝션 시도를 100% 감지하고 거부할 수 있다면 가드레일은 불필요한 지연 시간만 가중시킬 뿐이다.

하지만 범용 생성형 모델은 '사용자 지시 수행'이 최우선 목표이기 때문에, 평가 위장, 번역/인코딩 난독화가 개입될 경우 안전 지침보다 사용자 지시를 우선시하는 취약점이 빈번히 발생했다. 실제로 시스템 프롬프트가 주어지지 않은 순수 Gemma4 를 대상으로 '정형/비정형 공격 15종'을 직접 테스트해보았다.

## 왜 전용 가드레일 모델이 필요한가?
시스템 프롬프트가 주어지지 않은 상태의 Gemma4 는 대부분의 탈옥 및 주입 공격(15개 중 12개 실패, 3개 부분 허용)에 취약했다. 사용자의 명령을 그대로 수행했다.

- 메인 LLM 의 시스템 프롬프트에 `보안 규칙` 과 `가드레일 지침` 을 넣으면 방어해내겠지만, 다음과 같은 치명적 단점이 존재한다
  - 모든 사용자 요청마다 수백 ~ 수천 토큰의 시스템 가이드라인이 Prefill 되어 크게 지연된다
  - 가드레일 지침이 길어질수록 정작 사용자의 본래 지시사항을 무시하거나 오동작할 확률이 높아진다
  - 시스템 프롬프트 역시 LLM 의 컨텍스트 안에서 해석되기 때문에, 복잡한 인젝션 기법으로 여전히 덮어쓰기가 가능하다

- Kanana Safeguard Prompt 2.1B 도입의 이점
  - 메인 추론 앞단에 배치하여 단일 토큰 출력만으로 수십 ms 이내에 `Injection(A1)` 과 `Leaking(A2)` 를 완벽에 가깝게 차단할 수 있다
  - 메인 LLM 은 무거운 보안 지침 없이 순수 비즈니스 로직에만 리소스를 집중할 수 있어, <span style="color: var(--color-accent-impl);">시스템 전체의 처리량과 안정성을 모두 확보할 수 있다</span>
