## 마크다운을 쓰는 4가지 기술적 이점

### LLM 의 JSON 이스케이프(Escape) 참사 방지
- 2,000자에 달하는 소설 본문에는 수많은 큰따옴표("..."), 작은따옴표, 줄바꿈(\n), 특수문자가 포함된다.
- LLM 이 글을 작성하다가 <span style="color: var(--color-accent-spec);">따옴표 하나라도 이스케이프(\") 처리를 누락하면, 파이썬에서 json.loads()를 실행할 때 즉시 `JSONDecodeError` 가 발생하며 파이프라인이 멈춰버린다.</span>
- 마크다운은 따옴표나 줄바꿈에 대한 이스케이프 제약이 전혀 없다. LLM 이 아무런 구문 오류없이 가장 긴 문장을 안정적으로 생성할 수 있다.

### 토큰 효율 및 생성 품질
- Gemini, GPT, Claude 등 현대 LLM 의 사전 학습 데이터셋 중 가장 품질이 높은 텍스트는 GitHub 문서, 논문, 위키 등 마크다운으로 작성된 데이터다.
- XML 이나 복잡한 구조체보다 `#, ###, >` 같은 마크다운 구문을 사용할 때 LLM 이 Context 와 섹션 구분을 가장 정확하게 이해하고 생성한다.
- <span style="color: var(--color-accent-impl);">불필요한 태그나 JSON 키-값 쌍이 없기 때문에 입출력 토큰 소모량이 가장 적다.</span>

### 포터블한 단일 원천(Single Source of Truth, SSOT)과 플랫폼 확장성
- 만약 네이버 외에 티스토리, 노션, 혹은 전자책 등으로 발행하고 싶을 때, 네이버 전용 HTML 이나 DB 데이터는 <span style="color: var(--color-accent-spec);">다른 곳으로 옮기기 어렵다.</span>
- 반면 마크다운은 정적 사이트의 표준이므로, <span style="color: var(--color-accent-impl);">어디로든 확장할 수 있다.</span>
<br/>
<br/>

## 반대로 발생하는 트레이드오프
- 네이버 스마트에디터는 마크다운을 지원하지 않는 리치 텍스트 에디터이기 때문에 원문의 `### 2. 소설, **굵은 글씨**, [삽화 삽입 위치]` 같은 마크다운 기호를 그대로 붙여넣으면 네이버 에디터에 특수문자가 그대로 노출된다.
- 따라서, 네이버 <span style="color: var(--color-accent-spec);">전용 전처리 함수가 필요하다.</span>
<br/>
<br/>

## 보관 및 생성은 마크다운, 발행은 대상에 맞게

|구분|JSON / 구조화 데이터 방식|마크다운 중간 저장 방식 (현재 구조)|
|---|---|---|
|LLM 생성 안정성|따옴표/줄바꿈 이스케이프 깨짐 위험 높음|구문 에러 위험 0% (가장 안전)|
|토큰 소모량|JSON 구조 오버헤드로 토큰 소모 증가|최소 토큰 소모 (비용/속도 최적)|
|타 플랫폼 확장성|전용 파서 개발 필요|노션, 깃허브, 전자책 등 즉시 호환|
|디버깅 및 아카이빙|뷰어 없이는 읽기 불편함|VS Code, GitHub에서 완벽한 가독성|

마크다운은 단순히 가독성뿐만 아니라, <span style="color: var(--color-accent-impl);">LLM 의 파싱 에러를 원천 차단하고, 토큰 효율을 극대화하며, 향후 다른 플랫폼으로도 확장할 수 있는 우수한 중간 포맷</span>이기 때문에 선택하였다.
