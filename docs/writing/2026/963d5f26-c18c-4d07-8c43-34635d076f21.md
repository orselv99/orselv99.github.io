## 생성형 AI 의 반복에서 오는 피로도 줄이기

자동화 이후 몇 편이 올라갈 때까지는 나쁘지 않은 퀄리티였으나, <span style="color: var(--color-accent-spec);">모든 글에서 반복적으로 나타나는 인용구와 삽화위치 등 너무 AI 가 찍어낸 양산형 글임이 느껴졌다.</span> 이런 피로감을 줄이기 위해 컨텐츠 생성 프롬프트와 서식 파이프라인을 고도화해봤다.

### 서두 다변화
- 매 글마다 기계적으로 인용구를 넣지 않고, 3~4편 당 한번씩만 고전 인용구를 생성하도록 규칙을 변경
- 인용구가 없는 날에는 배경 설명 없이 이야기를 시작하거나, 인물의 대사 또는 감각적 묘사를 추가

### 네이버 스마트에디터'버티컬 라인' 위젯 연계
인용구가 사용되는 때에는, 네이버 스마트에디터의 `인용구 컴포넌트` 를 툴바에서 동적으로 호출했다.

```python
# 네이버 스마트에디터 공식 인용구 컴포넌트
q_opt_btn = editor_frame.locator("button.se-document-toolbar-select-option-button[data-name='quotation']").first
await q_opt_btn.click()
await editor_frame.locator("button[data-value='quotation_line']").first.click()

# 인용구 본문과 출처 분리 입력
await page.keyboard.insert_text(quote["text"])
cite_p = editor_frame.locator("div.se-cite p, .se-quotation-source").first
if await cite_p.is_visible():
    await cite_p.click()
    await page.keyboard.insert_text(quote["source"])

# 인용구 블록에서 안전하게 탈출하여 일반 본문 컴포넌트로 포커스 이동
await page.keyboard.press("ArrowDown")
await page.keyboard.press("Enter")
```

이로써 인용구가 들어갈 때에도 마크다운 기호 없이, 네이버 스마트에디터가 제공하는 다양한 스타일의 인용구 디자인을 적용했다.

## 다중 블록 컴포넌트(인용구-본문-삽화) 와 `Control+A`

네이버 스마트에디터의 본문 서식을 일괄 변경하기 위해 처음에는 문단 클릭후 전체 선택을 적용했다. 그러나 실제로 발행된 글을 확인해보니 의도대로 적용되지 않고 있었다. 

### 문제의 원인
<span style="color: var(--color-accent-spec);">스마트에디터는 본문 전체가 하나의 `contenteditable`이 아니었다.</span> 인용구, 본문, 삽화가 각각 독립된 React 컴포넌트로 격리되어 있었고, 그래서 `Control+A` 를 누르면 인용구 텍스트만 선택되었다. 설령 본문을 클릭하고 `Control+A` 를 누르더라도, 선택 범위가 중간에 삽입된 삽화를 건너뛰지 못해 이어지는 다음 본문은 서식 적용에서 제외됬던 것이다.

### 컴포넌트 단위별 스타일링 적용
DOM 트리를 순회하여 인용구, 삽화를 제외한 본문 텍스트 컴포넌트 목록만 추출한 뒤, 각 컴포넌트마다 포커스를 잡고 서식을 적용하게 변경했다.

```python
def apply_post_style(frame, page, style):
    # 인용구, 제목, 이미지를 제외한 실제 본문 텍스트 컴포넌트만 정확히 조회
    text_comps = frame.locator("div.se-component.se-text").all()
    
    font_fam = style.get("font_family", "기본서체")
    font_sz = style.get("font_size", 15)
    line_h = style.get("line_height", 180)

    for idx, comp in enumerate(text_comps):
        # 컴포넌트 내부 첫 문단 클릭
        p_first = comp.locator("p.se-text-paragraph").first
        p_first.click()
        page.wait_for_timeout(300)

        # 현재 텍스트 블록 전체 선택 (이미지 너머와 섞이지 않는 안전한 블록 셀렉션)
        page.keyboard.press("Control+A")
        page.wait_for_timeout(300)

        apply_font_size(frame, font_sz)     # 글자 크기 15pt 적용
        apply_font_family(frame, font_fam)  # 폰트 서체 '기본서체(system)' 적용
        apply_line_height(frame, line_h)    # 줄간격 180% 적용
        apply_align(frame, "left")          # 좌측 정렬 적용
```

<span style="color: var(--color-accent-impl);">중간에 몇 장의 삽화나 다른 위젯이 추가되더라도 본문의 스타일을 일괄 적용할 수 있게됬다.</span>

## 파이썬 `strip()` 의 유니코드 공백 삭제 

조사해보니 소설에서는 다양한 이유로 화자의 대사와 장면 해설을 들여쓰기로 구분한다. 아직은 의미부여나 기교를 요청하기에 AI 가 오류를 뱉어낼 것 같아서 충분히 시행착오를 겪은뒤 해보려고 한다. 대신 가독성을 위해서 화자의 대사에는 들여쓰기 없이 행의 맨 앞에서 시작하게하고, 장면 설명 문단은 첫 줄 들여쓰기를 의무화 하려했다.

### HTML 연속 공백 실패와 공백(`\u3000`) 추가
<span style="color: var(--color-accent-spec);">웹 브라우저의 렌더링 엔진이 문장 첫머리에 일반 스페이스(` `)를 여러 번 넣어도 이를 1칸으로 뭉개거나 아예 무시해버리는 것을 발견했다.</span> 이를 해결하기 위해 Unicode `\u3000` 를 추가했다. 웹 브라우저에서도 한글 한 글자(1em)와 정확히 동일한 가로 폭을 유지하며 들여쓰기를 만들어 준다. 정규식을 통해 대화문과 서술문을 자동 분리하고, 첫 문단에 `\u3000` 을 주입하는 전처리기를 적용했다.

### 파이썬 `str.strip()` 
원고 파일을 직접 열어보면 분명히 `\u3000` 가 있었는데도 이상하게 블로그에서는 들여쓰기가 적용되지 않았다. Playwright 가 스마트에디터에 타이핑을 마치고 발행된 포스팅을 보면 모든 들여쓰기가 사라지는 현상을 확인했다. <span style="color: var(--color-accent-spec);">그리고 그 원인은 파이썬 `str.strip()` 에 있었다. 인자 없이 호출하면 공백만 제거하는 것이 아니라, 추가한 유니코드 공백 '문자' 또한 공백으로 간주하여 없애버렸던 것이다.</span> 명시적으로 제거할 것만 지정하게 수정하고 나서야 의도한대로 동작하는 것을 확인했다.
```python
# [개선 전] 유니코드 공백 문자도 공백으로 간주하고 제거
line = paragraph.strip()

# [개선 후] 띄어쓰기, 탭, 개행만 제거
line = paragraph.strip(" \t\r\n")
```
