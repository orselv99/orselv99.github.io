## 1. 개요
LLM 의 판단 레이턴시를 줄이기 위해 사전필터로 리서치 중, PII 를 확인했고 GPU 사용이 필요없는 가벼운 리소스로 구동되도록 설계되어 있다는 것을 확인

## 2. CPU 만으로 충분한 이유
1. 규칙 및 정규표현식(Regex) 중심 처리
- 전화번호, 이메일, 주민등록번호, 신용카드 번호, IP 주소 등 정형화된 PII 대부분은 정규식과 체크섬(Checksum) 알고리즘으로 감지됩니다. 이 연산은 수 밀리초(ms) 단위로 끝나며 GPU 연산이 필요하지 않습니다.

2. 경량 NLP 모델 사용
- 이름이나 지명 등 문맥이 필요한 개체명 인식(NER)에는 기본적으로 spaCy의 경량 모델(en_core_web_sm 등)이 쓰입니다. 이 모델들은 CPU 추론에 최적화되어 있어 딜레이가 거의 없습니다.

3. 가벼운 익명화 연산
- 탐지된 문자열을 치환(Replace), 마스킹(Masking), 해싱(Hashing), 대칭키 암호화(AES)하는 작업은 순수 문자열 연산이라 CPU 점유율이 매우 낮습니다.

## 3. Features
1. Presidio Analyzer (presidio-analyzer)
- 비정형 텍스트 내의 민감정보(PII/PHI)를 탐지하는 핵심 엔진입니다.
- 정규표현식(Regex), 체크섬(Checksum) 유효성 검증, 사전 기반 매칭, 자연어 처리(NLP/NER) 모델(spaCy, Hugging Face Transformers 등)을 결합한 하이브리드 방식으로 작동합니다.   문맥 인식(Context-aware): 주변 단어(예: "연락처", "카드번호", "SSN")를 분석해 탐지 신뢰도 점수를 동적으로 보정합니다.   비즈니스 도메인에 맞춘 커스텀 Recognizer(인식기)를 손쉽게 추가할 수 있습니다.   

2. Presidio Anonymizer & Deanonymizer (presidio-anonymizer)
- Analyzer가 찾아낸 PII 영역을 다양한 비식별화 연산자로 변환합니다.   원문 복원이 필요한 경우 대칭키 기반 암호화와 복호화(Deanonymizer) 파이프라인을 지원합니다.
- 삭제, 대체, 마스킹, 해싱, 암호화 총 5가지를 지원

| 연산 방식 | 설명 | 예시 |
| --- | --- | --- |
| Redact (삭제) | 탐지된 민감정보 문자열을 완전히 제거 | `"홍길동 고객님"` → `" 고객님"` |
| Replace (대체) | 엔티티 타입 태그나 지정된 대체 텍스트로 치환 | `"홍길동"` → `"<PERSON>"` |
| Mask (마스킹) | 특정 문자로 가림 처리 (앞/뒤 노출 길이 설정 가능) | `"010-1234-5678"` → `"010-****-5678"` |
| Hash (해싱) | SHA-256 등의 단방향 해시값으로 변환 | 고유 식별성은 유지하되 원문 은닉 |
| Encrypt (암호화) | AES 대칭키로 암호화 (복호화 키로 역연산 가능) | 원문 재식별 권한이 필요한 경우 활용 |


3. Presidio Image Redactor (presidio-image-redactor)
- 이미지 내 텍스트를 OCR(Tesseract 등)로 추출한 뒤, PII가 포함된 좌표(Bounding Box)를 계산하여 시각적으로 검은 박스 처리(블랙아웃)하거나 흐리게 마스킹합니다.일반 이미지 포맷뿐 아니라 의료용 DICOM 영상 데이터의 민감정보 가림 처리도 지원합니다.   

4. Presidio Structured
- CSV, Pandas DataFrame, RDBMS 테이블과 같은 정형/반정형 테이블 데이터의 컬럼 단위 PII 탐지 및 익명화를 처리합니다.
